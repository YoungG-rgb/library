# Стандарты разработки

Каталог содержит правила «как делать X» для агентов и людей, работающих в любом backend-проекте на Spring Boot + JPA. Стандарты — imperative, бьются по узким темам, без воды.

## Когда использовать

- Перед созданием новой сущности / репозитория / сервиса — открой соответствующий файл.
- При код-ревью — ссылайся на правила из стандартов вместо переписывания обоснований.
- При расхождении со стандартом — либо обнови код, либо обнови стандарт (с обоснованием в PR-описании).

- [package-structure.md](package-structure.md) — структура пакетов (feature × layer).
- [jpa-entity.md](jpa-entity.md) — как создавать JPA-сущности.

## Правила ведения

- Стандарт = один файл = одна тема. Не сваливай всё в общий.
- Формат: короткие правила в bullet-форме, императив (`Делай X`, не «можно делать X»).
- Если в правиле есть «почему» — добавляй в формате `**Почему:**` после правила (одна-две строки).
- Примеры — только если правило неочевидное. `// ОК` / `// ПЛОХО` рядом.
- Не привязывай стандарт к конкретному проекту: не используй реальные имена пакетов, таблиц, файлов. Только обобщённые placeholder'ы (`OrderEntity`, `UserEntity`, `...services`).
- Стандарт не заменяет проектные конвенции (CLAUDE.md, AGENTS.md и т.п.) — они дополняют его проектной спецификой.
